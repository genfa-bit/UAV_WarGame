# 时间设置与运行记录

## 设置时间

主界面的“时间设置”可调整以下两项：

| 设置 | 默认 | 范围 | 生效方式 |
| --- | --- | --- | --- |
| 单步时长 | 0.22 秒 | 0.01–60 秒 | 每推进一步累加此时长；1× 播放间隔相同，2×/4× 加快播放 |
| 最大运行步数 | 2000 | 1–10,000 的整数 | 未自然分出胜负时，到上限以平局结束；完整记录改为增量存储前保持有界 |

部署或暂停时可修改，运行中须先暂停。已运行 30 步时，新上限至少为 31；非法输入会被拒绝，保留原设置。设置沿用至下一局及其他场景，不改变已经发生的事件时刻。

累计仿真时间与电脑实际耗时分别计量。例如前三步每步 0.22 秒，暂停后改为 0.5 秒，第四步的累计时间为 1.16 秒；前面三步的时间不会被重新计算。快速模式和 2×/4× 只改变播放速度，记录的仿真时间由每一步使用的时长决定。

现有机动、射击、反应、补给和通信延迟按时间步计算，单步时长用于时钟与播放间隔。改变单步时长不会将每步动作重新解释为连续物理模型。

## 查看事件

点击“运行记录”查看本局的记录。每条事件包含序号、发生步数、累计仿真时间、类别、说明及相关对象标识。列表显示最近 200 条，导出及自动保存保留全量。

| 类别 | 记录内容 |
| --- | --- |
| 侦察 | 单位发现或丢失目标 |
| 目标共享 | 信息进入共享池、实际到达和超时/失效；排队时刻与到达时刻区分记录 |
| 摧毁 | 单位或基地首次被摧毁的时刻；有明确攻击来源时记录击毁者 |
| 战术状态 | 单位行为、交战阶段、阵营态势及集火对象的变化，开局记录初始状态 |
| 结果 | 胜负、结束原因、总步数、累计仿真时间及终局统计 |
| 设置与过程 | 时间参数修改、开始、暂停、继续及返回部署等操作 |
| 交战 | 攻击、命中和伤害等战斗事件 |

摧毁时刻只记录一次，继续刷新、单步调用或打开结算不会重复写入结果。外部直接将对象生命值设为零时，记录摧毁时间但不推断不存在的击毁者。战术变化按步比较，避免每一步重复写入相同状态。

## 保存、导出与历史

每次开局创建独立运行编号。记录以 JSON 保存到用户数据目录下的 `runs`，Windows 默认位置为 `%LOCALAPPDATA%\UAV_WarGame\runs`；设置 `UAV_WARGAME_DATA_DIR` 时使用该根目录。

运行过程中每 50 步检查是否需要保存，自动完整保存至少间隔 5 秒，避免快速计算频繁重写文件；暂停、结束、返回部署、重新运行、切换场景及正常退出应用时立即保存当前记录。重新运行创建新编号，不覆盖上一局。历史区显示已保存对局的概览与文件位置，可点击“打开记录目录”查看文件；返回部署后仍可查看或导出上一局的内存记录。

运行、暂停及结束时均可手动导出记录，可按当前类别筛选。完整战报在结算后导出，同时包含场景信息、时间设置、单位状态、摧毁列表、全部事件及统计。格式版本为 3：在版本 2 的 `statistics`、`units`、`logs` 之外新增 `replay` 逐帧数据与 `map` 静态地图负载，版本 2 的旧文件仍可读取和导出，只是不能回放。

## 回放

每局的运行记录同时保存逐步的单位与基地状态（`replay` 块），因此任意一局打完的对战都能按帧完整回放。

| 入口 | 位置 |
| --- | --- |
| 回放本局 | 结算对话框的“回放本局”，读取刚打完这一局的已保存记录 |
| 历史行 | “运行记录”对话框历史区每行末尾的“回放”，可回放任意一局已保存记录 |
| 载入回放… | 底部工具栏，部署、运行、暂停与已结束状态都可用，用文件对话框选择任意位置的记录 JSON；回放中隐藏 |

回放中底部出现回放条：播放/暂停、上一帧、下一帧、进度滑块、当前累计时间与退出回放；顶部速度档位（1×/2×/4×/快速）同时可用。空格播放/暂停、左右方向键单步、Esc 退出回放。拖动时间轴或单步时，“运行记录”面板、战场统计与摧毁时刻都会同步到那一刻，点击单位可查看它在那一帧的属性与状态。攻击连线由该帧前后 7 步的交战记录与帧位置还原，因此不需要额外保存连线数据。

回放只读取记录文件，不新建也不覆盖任何 `runs` 下的文件；回放期间保存地图、返回部署、重新运行、载入地图与修改时间设置都会被拒绝。按 Esc 或“退出回放”回到进入回放前的部署：从运行、暂停或已结束状态进入时是本次运行前的部署；从部署阶段直接进入（例如刚启动程序、或刚返回部署后又编辑了布局）时是当时正在编辑的那份布局，不会退回上一局开跑前的旧布局。

`replay` 块的编码：单位顺序在首帧冻结（`unit_ids`，队尾为 `red_base`、`blue_base`），每单位每帧 7 个 int16（`x`、`y` 以 0.1 像素为单位，`hp`、`ammo`，`status`、`engagement` 为码表下标，`destroyed` 为 0/1），按帧与单位交织后整体 base64。码表 `status_codes`、`engagement_codes` 与 `field_layout` 随文件保存，只允许追加，解码时越界下标会被夹取。第 0 帧是部署态；帧号等于时间步，因此文件也保存了该局的单步时长与最大步数。每单位每帧 14 字节，10 单位 2000 步约 274 KB（base64 后约 365 KB），仍小于同局的 `records` 块。

回放沿用记录里的场景与地图负载，因此即使原场景文件之后被改动，回放画面仍与当时一致。除下列定性字段外，统计面板显示的是游标处的真值：集火目标、发现目标数、行为标签与 `winner`/`finish_reason` 沿用该局最终值；步数、累计时间、剩余/摧毁、攻击/命中/伤害、战斗力、态势与基地耐久为当前帧的真值。单位当前的锁定目标不写入帧数据，回放时为空。

自动保存使用同目录临时文件完成后替换目标文件。保存失败会保留内存记录并提示错误，可改用手动导出到其他目录；突然断电或强制结束进程可能丢失最后一次自动保存之后的事件。

## 验收步骤

1. 部署时将单步时长改为 0.5 秒、最大步数改为 10，开始并暂停。
2. 单步两次，确认步数为 2、累计时间为 1 秒；将单步时长改为 1 秒。
3. 再单步一次，确认累计时间为 2 秒，前两步记录仍使用原时刻。
4. 打开运行记录，依次筛选侦察、共享、战术与摧毁，导出全量文件核对序号和对象标识。
5. 运行至结束，确认出现唯一结果事件、步数不超过设置上限。
6. 重新运行，确认生成新编号、时钟归零，历史仍保留上一局；重新启动后检查已保存的历史概览。
7. 在结算对话框点“回放本局”，确认停在末帧；把进度滑块拖回第 0 步，确认单位回到部署位置、统计与运行记录同步回退；播放到某次摧毁前后，确认残骸与攻击连线正确；按 Esc 退出，确认回到原部署且 `runs` 目录没有多出文件。
8. 打开“运行记录”，点一条历史记录的“回放”；再点一条版本 2 的旧记录，确认按钮置灰并提示“旧版本记录，未包含逐帧数据，暂不支持回放”。
