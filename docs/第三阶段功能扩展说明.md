# 第三阶段功能扩展说明

## 本阶段目标

第三阶段只进行兵种体系重构，不实现手动部署，也不大幅修改已有战斗规则。目标是让系统从“UAV/UGV/CommandNode”升级为更清晰的空中、地面、指挥三类平台，并通过 UnitFactory 支持后续扩展。

## 兵种体系设计

系统新增平台类型 `UnitDomain`：

- `air`：空中单位。
- `ground`：地面单位。
- `command`：指挥节点。

当前具体兵种：

| 兵种 | unit_type | 平台 | 特点 |
| --- | --- | --- | --- |
| ScoutDrone | scout_drone | air | 高速、高侦察、低攻击 |
| StrikeDrone | strike_drone | air | 中速、中攻击、适合打击 |
| GroundVehicle | ground_vehicle | ground | 低速、高生命、高攻击 |
| MissileVehicle | missile_vehicle | ground | 远程、高伤害、低弹药 |
| CommandNode | command_node | command | 不移动、核心节点 |

## 空中单位与地面单位区别

- 空中单位：只受地图边界限制，可以越过普通地面障碍物。
- 地面单位：不能进入障碍物，若下一步进入障碍物则停止。
- 指挥节点：速度为 0，不移动。

## Unit 基类接口

`Unit` 基类统一包含：

- `id`
- `name`
- `team`
- `domain`
- `unit_type`
- `x`
- `y`
- `hp`
- `max_hp`
- `speed`
- `detect_range`
- `attack_range`
- `attack_power`
- `ammo`
- `status`
- `can_attack_air`
- `can_attack_ground`

核心方法：

- `is_alive()`
- `distance_to(other)`
- `can_detect(other)`
- `can_attack(other)`
- `take_damage(amount)`
- `move_towards(target_x, target_y, battlefield)`
- `move_away_from(enemy, battlefield)`

## UnitFactory 工厂模式

新增 `core/unit_factory.py`，通过注册表创建单位：

```python
UNIT_REGISTRY = {
    "scout_drone": ScoutDrone,
    "strike_drone": StrikeDrone,
    "ground_vehicle": GroundVehicle,
    "missile_vehicle": MissileVehicle,
    "command_node": CommandNode,
}
```

优点：

- `scenario_loader.py` 不需要大量 if-else。
- 未知 `unit_type` 会抛出清晰错误。
- 后续新增兵种时，只需新增类并注册。

## JSON 场景格式变化

第三阶段场景单位使用 `unit_type` 字段：

```json
{
  "id": "R-SD-1",
  "name": "红-侦察无人机",
  "team": "red",
  "unit_type": "scout_drone",
  "x": 85,
  "y": 110
}
```

默认属性由兵种类决定，不需要在 JSON 中写入全部属性。

## 后续扩展方向

1. 增加防空单位，让 `can_attack_air` 和 `can_attack_ground` 真正参与规则差异。
2. 增加维修车、电子干扰无人机等支援单位。
3. 增加部署阶段，由用户选择兵种和初始位置。
4. 为地面单位增加 A* 路径规划。
5. 增加兵种图标和单位详情面板。
