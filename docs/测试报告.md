## 战局回放（2026-10-16）

运行记录由格式版本 2 升为 3，在原有 `statistics`、`units`、`logs` 之外新增 `replay` 逐帧负载与 `map` 静态地图负载，因此任意一局已保存的对战都能以当时的画面按帧重放。逐帧数据把单位顺序冻结在首帧（队尾为红蓝基地），每单位每帧 7 个 int16（位置以 0.1 像素为单位、生命、弹药、状态与交战阶段码表下标、摧毁标志），按帧与单位交织后整体 base64；第 0 帧为部署态，帧号等于时间步。每单位每帧 14 字节，10 单位 2000 步原始约 274 KB（base64 后约 365 KB），仍小于同局的 `records` 块，[时间设置与运行记录](时间设置与运行记录说明.md#回放) 与 [回放检查记录](verification/replay-checks.json) 记录了编码、体积与取舍。

回放复用的是同一份 `snapshot()` 字典，界面层没有并行的回放视图模型，因此单位 Repeater、小地图、攻击连线画布、单位详情与统计面板都不需要回放分支。攻击连线由该帧前后 7 步的交战记录与帧位置还原，与实时快照逐字段一致，因此不需要额外持久化连线数据。统计面板中步数、累计时间、剩余/摧毁、攻击/命中/伤害、战斗力、态势与基地耐久是游标处的真值；集火目标、发现目标数、行为标签与胜负字段沿用该局最终值，这一点在文档中已注明。

回放期间不新建也不覆盖 `runs` 下的任何记录文件，该性质由逐字节比较的回归用例与源码自检第十组检查 `replay_last_run_without_touching_journals` 共同覆盖；回放中保存地图、返回部署、重新运行、载入地图与修改时间设置都会被拒绝。版本 2 的旧记录仍照常进入历史列表并可导出，只是历史行的“回放”按钮置灰并说明“旧版本记录，未包含逐帧数据，暂不支持回放”，不做迁移或回填。

底部工具栏的“载入回放…”在部署阶段也可用，刚启动程序即可回看任意旧记录；回放进行中该按钮隐藏，避免与回放条重复。进入回放时控制器会记下当时的那份部署，退出时恢复它：从运行、暂停或已结束状态进入时是本次运行前的部署，从部署阶段进入时是当时正在编辑的布局。后者是必要的——部署态的 `_run_deployment` 已被 `reset()` 清空，若沿用旧的回退逻辑，退出回放会把用户刚编辑过的单位与障碍一并退回场景初始布局。

源码自检本轮增加至十组（[回放检查记录](verification/replay-checks.json) 列出了十个检查名）；`verification/source-smoke.json` 仍是 2026-10-11 的九组证据，未在本轮重新生成。回放第 0 步的离屏截图见 [回放](verification/replay-1280x720.png)：顶部状态为“回放暂停”，右侧为战局回放侧栏，底部为回放条。尚未验证的部分只有真实鼠标拖动进度滑块的连续手感，以及无 Python 的独立 Windows 机器上的回放，离屏事件测试不能代替这两项。
