# 第五阶段功能扩展说明

## 1. 本阶段目标

第五阶段围绕攻击结算与战斗表现增强展开，目标是在不重写部署阶段和兵种体系的前提下，补齐攻击规则、单位销毁、胜负判断、战斗日志、战斗统计、可视化反馈和自动化测试。

## 2. 攻击结算流程

攻击规则集中在 `core/combat.py` 的 `CombatSystem` 中，单位能力判断沿用 `Unit.can_attack()`。

一次攻击必须满足：

- 攻击者未被摧毁。
- 目标未被摧毁。
- 攻击者 `ammo > 0`。
- 目标在 `attack_range` 内。
- 攻击者具备目标平台攻击能力：空中目标要求 `can_attack_air=True`，地面和指挥目标要求 `can_attack_ground=True`。

攻击成功后：

- 攻击者消耗 1 发弹药。
- 攻击者状态切换为 `Attack`。
- 目标扣除实际伤害，生命值不低于 0。
- 生成 `AttackEvent`，用于日志、统计和攻击连线特效。

## 3. 兵种攻击差异

- `ScoutDrone`：攻击力低、弹药少、探测范围较高，主要承担侦察任务。
- `StrikeDrone`：中等攻击力和中远攻击范围，可攻击空中和地面目标。
- `GroundVehicle`：攻击力较高、攻击范围中等，可攻击地面目标，是否防空由 `can_attack_air` 字段控制。
- `MissileVehicle`：远程高伤害、弹药少，适合远程打击。
- `CommandNode`：默认 `attack_power=0`、`ammo=0`，不主动攻击。

## 4. 销毁规则

当单位 `hp <= 0` 时：

- `hp` 固定为 0。
- `status` 设置为 `Destroyed`。
- `target_id` 清空。
- 不再移动、侦察或攻击。
- 不再进入共享目标池和集火目标选择。

渲染层仍显示灰色残骸，便于课堂演示战斗过程；逻辑层通过 `active_units()` 和目标池清理排除已摧毁单位。

## 5. 胜负判断规则

本阶段采用“所有单位都算有效单位”的简单规则，`CommandNode` 不作为单独失败条件：

- 红方所有非 `Destroyed` 单位被消灭，蓝方获胜。
- 蓝方所有非 `Destroyed` 单位被消灭，红方获胜。
- 双方同时无存活单位，判定平局。

胜负结果保存在 `Simulator.winner`，并通过 `status_snapshot()` 提供给信息面板。

## 6. 战斗统计设计

`Simulator` 维护以下统计：

- 红方剩余单位数、蓝方剩余单位数。
- 红方击毁数、蓝方击毁数。
- 红方攻击次数、蓝方攻击次数。
- 红方总伤害、蓝方总伤害。
- 当前仿真时间步。
- 胜负结果。

其中击毁数按攻击归属统计，初始即为 `hp=0` 的单位只计入损失，不计入任一方击毁数。

## 7. 战斗日志设计

`Simulator.combat_logs` 保存最近 8 条日志，超过后自动丢弃旧日志。日志同时输出到控制台，并在信息面板显示最近若干条。

日志类别包括：

- `[Scout]`：侦察发现。
- `[Attack]`：攻击事件。
- `[Destroyed]`：单位被摧毁。
- `[Result]`：胜负结果。
- `[Evade]`：单位进入规避状态。
